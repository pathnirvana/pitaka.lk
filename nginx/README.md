# nginx config for pitaka.lk
The pitaka.lk vhost and the old-link map, versioned here. Not deployed by `dev/deploy.sh` (it needs sudo).
Since the move to the tipitaka.lk droplet (`dev/migrate.sh`), the vhost sends `/main/` to the new reader
(`pitaka_lk.service` on port 8403, the pitaka flavor of pathnirvana/tipitaka.lk) and serves the static sites from
`/home/janaka/www/pitaka.lk`.

| File | On the server |
|---|---|
| `pitaka.lk.conf` | `/etc/nginx/conf.d/pitaka.lk.conf` |
| `nodeid_mapping.map` | `/etc/nginx/conf.d/nodeid_mapping.map` |

`nodeid_mapping.map` maps the old Sarala Tipitaka node ids (`/main?n=15100`, `/15100`) to tree keys
(`dn-1-1`). It was generated by misc-projects/ai-trans/bjt/apz-redirect/generate_redirects.js. The vhost sends
those links to `https://pitaka.lk/main/<key>`, and ids that are not in the map to `/main/`.

Install after a change:
```
scp nginx/pitaka.lk.conf nginx/nodeid_mapping.map tipitaka.lk:/tmp/
ssh -t tipitaka.lk 'sudo cp /tmp/pitaka.lk.conf /tmp/nodeid_mapping.map /etc/nginx/conf.d/ && sudo nginx -t && sudo systemctl reload nginx'
```
